# FSP — Fulfillment Services Protocol

Открытый стандарт услуг фулфилмента: прайс оператора, свободные мощности и заявка описываются машиночитаемо. Чтобы сравнить двух операторов, не нужно созваниваться и пересылать Excel.

Спецификация: **[openfsp.ru](https://openfsp.ru)** · Версия протокола: **1.0** · Статус: `READY`

## Из чего состоит

Протокол собран из модулей. Каждый версионируется отдельно, поэтому правка в описании цен не поднимает версию каталога услуг и не заставляет никого переделывать интеграцию.

| Модуль | Версия | Статус | О чём |
|---|---|---|---|
| [`core`](modules/core) | 1.0 | stable | Услуги, единицы начисления, категории, габариты, оператор и склад |
| [`pricing`](modules/pricing) | 1.0 | stable | Как оператор описывает прайс; уровни L1/L2/L3 |
| [`capacity`](modules/capacity) | 1.0 | stable | Что готов взять, сколько свободно, куда возит |
| [`quote`](modules/quote) | 1.0 | stable | Запрос сметы и ответ |
| [`order`](modules/order) | — | planned | Поставка, отгрузка, возврат |
| [`tracking`](modules/tracking) | — | planned | События по заказу и остатки |

`order` и `tracking` не описаны намеренно: спецификация вперёд спроса переписывается после первой живой интеграции.

## Три вещи, на которых стоит протокол

**Сторона объявляет, что умеет.** Манифест по адресу `/.well-known/fsp` перечисляет поддерживаемые модули, версии и уровни. Две стороны сводят манифесты и работают по пересечению, а не по переписке ([`profile/`](profile)).

**Уровни вместо порога входа.** Прайс из Excel описывается на L1 за вечер. Условия и модификаторы это L2, ступенчатые тарифы L3. Требование уровня выше не выкидывает оператора из выдачи, а возвращает понятный код: задачу, а не отказ.

**Промах объясняется кодом.** Ответ на запрос сметы несёт `unmet` из закрытого реестра из 21 причины: не берёт категорию, нет режима хранения, объём ниже минимального. Заявитель понимает, почему выдача узкая, оператор видит, что поправить.

## Быстрый старт

```bash
git clone https://github.com/open-fsp/fsp.git
cd fsp && python3 validate.py
```

40 блокирующих проверок: ссылочная целостность реестров, состав и зависимости модулей, уровни соответствия, перечисления схем против реестров, разрешимость ссылок между схемами, примеры манифестов. Exit 0 — публикация разрешена, exit 1 — блок. Зависимостей нет, нужен только Python 3. Гоняется в CI на каждый PR.

Пять проверок из сорока помечаются `SKIP`: им нужны данные разбора реальных прайсов, которые мы не публикуем — см. [`appendix/README.md`](appendix/README.md).

## Структура

```
modules/       модули стандарта: манифест, реестры, нормативные правила, JSON Schema
profile/       манифест /.well-known/fsp, правила согласования, примеры
api/           OpenAPI модуля Quote
appendix/      проверки валидатора и открытые дыры покрытия — не входит в стандарт
site/          витрина openfsp.ru: страницы генерятся из реестров
validate.py    валидатор целостности
```

Витрина ничего не дублирует руками: таблицы реестров, текст спецификаций, правила и числа собираются из канона при сборке, поэтому разойтись со стандартом не могут. Машиночитаемые артефакты отдаются по постоянным адресам `/1.0/<модуль>/schema.json`, реестры в JSON и CSV, плюс `/llms.txt` для агентов.

## Как править

Правка проходит через pull request, и решает не спор в переписке, а валидатор — [`CONTRIBUTING.md`](CONTRIBUTING.md).

Своя операция, которой нет в стандарте, оформляется расширением `x-<vendor>:<code>` в манифесте, а не ожиданием новой версии.

## Кто ведёт

Стандарт ведёт МПФИТ — облачная WMS для фулфилмент-центров и селлеров, она же первая реализация. Протокол выделен из её внутреннего стандарта каталога услуг (версии 1.0–1.3, первая половина 2026 года), где всё жило одной версией: правка в модели цены поднимала версию каталога услуг, и потребитель был обязан выяснять, что именно сломалось. Разделение на независимо версионируемые модули, манифест согласования и уровни соответствия появились при выделении.

Какую задачу решает протокол и с чего начать реализацию — [`ABOUT.md`](ABOUT.md).
