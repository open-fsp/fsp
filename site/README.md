# Витрина openfsp.ru

Astro-сайт стандарта. Ничего не дублирует руками: страницы собираются из реестров, манифестов, схем и README модулей, которые лежат уровнем выше. Если канон изменился, сайт меняется при следующей сборке — разойтись со стандартом он не может.

```bash
cd site
npm install
npm run dev        # http://localhost:4321
npm run build      # статика в site/dist
```

## Что откуда берётся

| На сайте | Источник |
|---|---|
| Таблицы реестров | `modules/*/*.csv`, `appendix/*.csv` |
| Текст спецификации модуля | `modules/<модуль>/README.md` |
| Состав, версия, зависимости | `modules/<модуль>/module.json` |
| Нормативные правила | `rules.csv` каждого модуля |
| Манифест и согласование | `profile/README.md`, `profile/examples/*.json` |
| Чейнджлог | `CHANGELOG.md` |
| Числа на главной | считаются из реестров, руками не проставлены |

Разбор канона — в [`src/lib/standard.js`](src/lib/standard.js). Относительные ссылки внутри README переписываются на страницы витрины; то, что не разложилось, уходит на GitHub, а не в 404.

## Постоянные адреса

Машиночитаемое отдаётся под `/1.0/` и совпадает с `$id` схем, поэтому относительные `$ref` между схемами разрешаются как есть:

```
/1.0/<модуль>/schema.json          JSON Schema сущностей
/1.0/<модуль>/module.json          манифест модуля
/1.0/<модуль>/<реестр>.json        реестр как массив объектов
/1.0/<модуль>/<реестр>.csv         реестр как есть
/1.0/profile/fsp-profile.schema.json
/1.0/quote/openapi.yaml
/llms.txt                          карта стандарта для агентов
```

Поэтому `trailingSlash: "ignore"`: адреса артефактов оканчиваются на расширение и слеша не терпят.

## Деплой

Сборка статическая, без серверной части: `site/dist` кладётся под любой веб-сервер. Требования к хостингу — только отдача файлов как есть и правильные типы для `.json`, `.csv`, `.yaml`.

Что нужно, чтобы витрина открылась на openfsp.ru:

1. A-запись домена на сервер.
2. TLS-сертификат.
3. Раздача `site/dist` как корня сайта, `404.html` на несуществующие пути.
4. Сборка при изменении канона: `npm ci && npm run build` в `site/`.

## Чего на витрине нет

Реализация МПФИТ (`docs/marketplace.md`) и демо-песочница (`demo/`) — это применение стандарта, а не сам стандарт. На сайт они не выкладываются, ссылки ведут в репозиторий.
