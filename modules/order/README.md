# FSP Order — планируется

Заказ как объект обмена между заявителем и оператором: поставка на склад, отгрузка, возврат.

Статус `planned`: реестров нет, объявить модуль в манифесте нельзя.

## Почему не описан

Спецификация, написанная вперёд спроса, переписывается после первой живой интеграции. Модуль описывается тогда, когда появится сторона, которой он нужен для обмена, — и описывается под её реальный сценарий.

## Что войдёт

- Поставка: что и в каком количестве едет на склад, ожидаемая дата, состав тары.
- Отгрузка: заказ на выдачу, маршрут из [FSP Capacity](../capacity), окно отправки.
- Возврат: источник возврата, решение по товару (на полку, в брак, восстановление).
- Связь с [FSP Quote](../quote): принятая смета как основание заказа.

События по заказу и остатки — отдельный модуль [FSP Tracking](../tracking).
